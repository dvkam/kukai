# Shared experiment cases

Run a positive control with a valid quorum before each negative variant. Use synthetic identities, temporary test keys, and local or sandbox chain state. Give the case a new run ID on each execution. Set the candidate, protocol revision, roles, initial generation, request, and expected result before recording observations. Preserve the path and assumptions of every referenced [source obligation](../verification/initial-obligations-v0.1.json). A passing example establishes behavior in that run.

| Case and obligations | Initial state and intervention | Expected observation |
| --- | --- | --- |
| AUTH · 1, 2, 8 | Begin with a valid approved request. In separate runs withdraw approval, use only a recovered social login, and give the coordinator and service share to the same actor. | The control verifies through the chain library. Attempt recovery and enrollment separately as social-only and as signer plus coordinator without user material. Both must fail to complete recovery or enroll a replacement device through that path. No unauthorized service release occurs under the honest-signer assumption. Without user material the compromised service and coordinator lack quorum. |
| PRIVACY · 3 | Trace each secret type to its host, transport and storage for the pinned implementation. Compare the protocol variant and assumptions with its proof and audit coverage. | Record the evidence and gaps. An implementation with unreviewed departures retains an open assumption. Observing redacted traces cannot establish cryptographic privacy. |
| BIND · 4, 7, 15(a) | Approve one request. Replay its approval in another session, account and chain. Change recipient, amount, calldata, simulation reference and renderer version separately. Test S and the honest local display on X where applicable. | Every mismatched context requires new approval or refusal. Retain the unchanged control and evidence that the other digest could not use its approval. Test the source's alternative client and signer assumptions independently for obligation 4. |
| LIMIT · 1, 15(b) | Use two sessions and devices sharing a cumulative limit. Each request fits alone, but both exceed the limit together. Pause both before reservation and release them in both orders. Then request a zero-value operator grant. | Under an honest signer, a reservation accounts for other pending requests atomically. High exposure and permission changes require independent enrolled iOS approval of the same digest. Release, crash and retry must preserve the accounting. |
| CUTOFF · 5, 12(a) | Withhold, reorder and duplicate the release message. Record revocation before and after the protocol-specific irreversible release. Attempt a new session with the old generation. | Revocation before the cutoff prevents completion on S. Already released sufficient material can complete. A previously assembled signature retains chain-specific validity. Reject old login sessions. Destroy outstanding presignatures and verify that a restart cannot restore or consume them. Record physical erasure as an assumption where the implementation can only demonstrate logical deletion. |
| RECOVER · 2, 6, 14 | Run separately with the old device lost, destroyed, stolen and intermittently connected. Drop notifications, issue repeated objections, then remove the extra dispute factor in a separate run. Advance a controlled clock across each boundary. | Attempt every enrolled channel and retain attempt records. No completion before the applicable delay. The first eligible objection sets a longer deadline and requires the additional factor. Repeated objections leave that deadline unchanged. With a stolen device, only the claimant holding the extra factor, and all other completion conditions met, verify completion when the fixed dispute delay ends. Distinguish thief-induced delay from delivery and chain availability. Under the stated fairness and factor assumptions, a claimant with a lost or destroyed device completes recovery after the delay even if no notification arrives. Losing the dispute factor removes that progress guarantee. Freeze symbolic deadlines before timing tests. |
| FACTOR · 9, 14 | Build a reachability table for provider reset, sync, backup ciphertext and decryption. Give a tester the unlocked device alone and attempt to unlock the recovery share. Reject an A1 pairing that yields both shares. Take over each single provider account and separately give the service all routine admin access. | A supported single-account recovery cannot satisfy both identity and user-factor requirements. For every actor able to reach the service share, test access to the recovery share and to its unlocking factor separately. Either path blocks the candidate, even if ciphertext is currently unavailable. Record rejected provider pairings. |
| TRANSCRIPT · 10, 11 | Swap participant IDs, replay a DKG round, substitute public keys, or show different broadcasts to two honest clients. Repeat equivocation during signing with inconsistent commitments or signing packages. Run healthy delivery, delayed delivery, and one missing participant as controls. | Honest clients agree on roster, group key and derived address before funding, or abort on inconsistency. During signing, require consistent authenticated broadcasts or a recorded abort before release. A missing required participant may block progress. Document any trusted broadcast assumption and the consequence of breaking it. |
| REPLACE · 12(b), 17 | Retain one old share, refresh on a supported curve, then mix it with a current share. Interrupt before committing every new package and restore an offline backup. Test the complete retained old quorum separately. | A successful transition leaves a current exit quorum. Mixed generations cannot sign. A retained old quorum remains a residual if erasure fails. Recovery from interruption must never declare success with mismatched user-held state. |
| MOVE · 12(c), 16 | Remove every project-operated service. Sign directly through the exit tool. Export each supported exportable key, import into an independent verifier or wallet and verify control of the original account. For each non-exportable format exercise the signing and migration path. Move a test balance, migrate a role, revoke an approval and record an immovable test asset. Send a new test deposit to the old address afterward. Repeat with public RPC unavailable. | Record independently verified ownership, permissions and explicit exceptions for each asset. Only completed moves gain the new key's protection. Track the later deposit under the old key. Record blocked settlement during chain outage. |
| AGENT · 13 | In a future agent-enabled build, give the agent a limited grant. Request a grant increase, an unsupported chain and a new signing authority. | Policy denies every escalation. Record this as deferred until that role exists. |
| RESTORE · 5, 17 | Interrupt before and after consuming ephemeral signing state. Restore an earlier backup twice while a request is pending, then retry signing in a fresh session. | The restored state contains no nonce, presignature or prior session. Never reuse a consumed item. Each completed restore strictly increases the device generation. Two successful restores yield three ordered generations. The service rejects either earlier generation. Test release-after-crash separately against the cutoff. |
| UPGRADE · 7, 11, 15, 16 | Pin two protocol configurations with different operation capabilities. Switch the node after simulation or cached capability discovery. | Re-read capabilities, invalidate stale simulation and require fresh approval when context changes. Preserve address recognition while disabling unsupported operations. Report protocol revision and block reference. |

## Retained evidence

Record the commit, dependency lock digest, tool versions, device and runtime, case ID, configuration, controls, exit status and output digest in the ticket's evidence directory. Keep an allowlist of trace fields before capture. Use synthetic participant, account, event, request and session identifiers, public operation classes, component-local event counters, generation numbers and the expected and observed verdict. Correlate sends and receives by synthetic message IDs. A component-local clock orders that component's events only.

Exclude live shares, plaintext backups, secrets used to derive test keys, identity tokens, passkeys, recovery factors, nonces, presignatures, raw protocol traffic and personal identifiers. Use test-only chain receipts or public digests for transaction evidence. Check the retained artifact before committing it. An unmapped event, impossible transition or unexplained gap fails trace validation. The underlying security claim remains inconclusive. Missing evidence also leaves the claim inconclusive. An unexpected release, repeatable counterexample or broken assumption reopens the affected candidate or proof obligation. [Evidence template](../capabilities/experiment-template.md)
