## Outcome

Build the open-source exit prototype and prove that the user can operate it without our authorization or infrastructure.

## Blocked by

- [P3-01: Validate the minimum keys and decide derivation](p3-01.md)
- [P2-09: Decide fees, data services and operational boundaries](p2-09.md)

## Acceptance criteria

- [ ] Use the Phase 2 export and quorum decisions. A1 uses its user-held pair; B uses its full required user-held quorum.
- [ ] Block every project-operated host, including login, signing, metadata, download and recovery services. Run from retained artifacts and user-held material on a clean machine.
- [ ] Sign with each minimum key, reconstruct exportable keys, and verify exported formats with an independent implementation. Demonstrate Ed25519 signing without claiming conversion to a standard seed.
- [ ] Move transferable test assets and revoke or move supported authorities. Record fees, public-node dependencies, timelocks, frozen assets, non-transferable assets and old-address exposure.
- [ ] Repeat after supported recovery and share-lifecycle changes. Verify stale recovery material cannot silently strand a user whose exit quorum was claimed to be current.
- [ ] Publish reproducible commands, dependency records and an asset/authority coverage matrix. Include every optional key before its final admission.

## Evidence

Exit-tool source, a blocked-host configuration, independent verification results and a full exit-drill report.

## Failure or deferral

Any dependency on project authorization or share release fails the drill. A minimum-key failure blocks G3; document blockchain availability separately.
