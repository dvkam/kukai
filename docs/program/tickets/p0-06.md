## Outcome

Give Phase 2 a reviewable list of properties and assumptions before anyone writes the models.

## Blocked by

- [P0-01: Record the charter and assign the open decisions](p0-01.md)
- [P0-03: Verify cryptographic libraries and development toolchains](p0-03.md)

## Acceptance criteria

- [ ] Assign each obligation its covered paths, trust assumptions, safety or liveness classification and gate. Preserve the non-waivable set in v0.5.1.
- [ ] Map each property to a tool and an expected evidence format. Record why that tool can express and check it, including any bounds.
- [ ] Define expected failures when an assumption breaks. Record how the reviewer distinguishes a named residual risk from an unexpected counterexample.
- [ ] Define mutation checks, trace event mappings, model review and result statuses. Keep bounded checks and recorded-trace conformance separate from unbounded proof.
- [ ] Freeze the initial list before Phase 2. Require a reviewed change record for later refinements; never silently remove a difficult property.

## Evidence

A versioned obligation list, tool map, review policy and frozen-list identifier.

## Failure or deferral

An unexpressible mandatory property requires a design or verification decision. Do not replace it with an easier test without review.
