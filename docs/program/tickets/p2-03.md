## Outcome

Measure whether a pinned Ed25519 implementation supports the proposed user-held quorum on iPhone and in WebAssembly.

## Blocked by

- [P2-01: Model trust boundaries and define the experiment suite](p2-01.md)
- [P1-01: Choose the audience and supported onboarding conditions](p1-01.md)

## Acceptance criteria

- [ ] Run DKG and signing with separate Solana and Tezos keys. Check signatures with the relevant chain libraries or nodes.
- [ ] Demonstrate service-free signing with the user-held quorum. Record any export-format limitations without inventing a seed conversion.
- [ ] Exercise refresh, repair and participant replacement only where the pinned library supports them. Test stolen shares and retained old shares separately.
- [ ] Test recovery-share updates, offline recovery material and interrupted refresh. After every completed lifecycle change, prove that the current user-held material still forms an exit quorum.
- [ ] Measure DKG and signing latency on the reference iPhone and browser. Record the protocol cutoff, nonce handling, rounds and failures.

## Evidence

Runnable test-key experiments, chain-verifier results, lifecycle traces and raw latency samples.

## Failure or deferral

A missing safe recovery or exit path blocks custody selection for this minimum curve. Report capability gaps without custom cryptography.
