# P2-05: Select or defer the threshold BLS scheme

| Field | Value |
| --- | --- |
| Phase | 2 |
| Type | Decision |
| Status | Draft |
| Owner | Unassigned |
| Required roles | Cryptography engineer and Tezos reviewer |
| Decision targets | Q-28 |

## Outcome

Decide whether a reviewed BLS candidate merits a tz4 admission experiment in Phase 3.

## Blocked by

- [P2-01: Model trust boundaries and define the experiment suite](p2-01.md)

## Acceptance criteria

- [ ] Compare candidate licenses, pinned implementations, protocol proofs, audits and platform support.
- [ ] Check Tezos signature encoding, domain separation and the proof of possession needed for a tz4 reveal against the pinned Octez protocol.
- [ ] Record DKG, recovery, refresh, repair and user-quorum exit capabilities. Separate library support from unimplemented research.
- [ ] Select a candidate with a funded experiment, or record that owned tz4 is deferred while address recognition remains in scope.

## Evidence

A BLS decision with primary sources and explicit Phase 3 entry criteria.

## Failure or deferral

Deferral is a valid outcome for this optional key type. It must not prevent the minimum curves from progressing.
