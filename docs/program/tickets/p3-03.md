## Outcome

Test the P-256 threshold path before committing to owned tz3 accounts.

## Blocked by

- [P2-12: Review G2 against the minimum curves](p2-12.md)

## Acceptance criteria

- [ ] Confirm pinned P-256 implementation support, reviewed assumptions and applicable advisories.
- [ ] Test DKG, signing, reveal and Tezos-native verification on the reference iPhone and browser.
- [ ] Demonstrate recovery, L1 behavior, migration where L2 is unavailable, user-quorum reconstruction and service-free exit.
- [ ] Record latency, review booking scope and an admit, defer or fail recommendation. A funded experiment can still fail admission.

## Evidence

A tz3 admission report with reproducible cases or an explicit deferral decision.

## Failure or deferral

Unavailable safe refresh is not cured by restoring a backup. Defer tz3 if the compromise or exit requirements cannot be met.
