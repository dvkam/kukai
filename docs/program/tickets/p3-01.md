| Field | Value |

## Outcome

Extend the Phase 2 prototypes into reproducible admission evidence for Solana, Tezos tz1, Ethereum and Base.

## Blocked by

- [P2-12: Review G2 against the minimum curves](p2-12.md)

## Acceptance criteria

- [ ] Decide one DKG per key versus supported derivation from measured costs and scheme constraints. Keep separate keys across chain families.
- [ ] Pin the implementations and all relevant features. Obtain external review of protocol assumptions and implementation departures.
- [ ] Verify signatures and representative transactions through chain-native verifiers, including Tezos watermarks and EVM chain binding. Include malformed and replayed inputs.
- [ ] Test malicious coordinator behavior, authenticated broadcast and address derivation from the client's DKG transcript.
- [ ] Publish reproducible builds and experiment results on the reference iPhone and WebAssembly runtime. Reuse valid Phase 2 evidence and rerun cases affected by changed code or decisions.

## Evidence

A derivation decision and minimum-key compatibility and protocol-review reports.

## Failure or deferral

Any minimum key that fails admission holds release 1. A verifier accepting signatures is compatibility evidence, not an audit.
