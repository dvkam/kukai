# P2-04: Test secp256k1 recovery and independent signing

| Field | Value |
| --- | --- |

| Type | Experiment |
| Status | Draft |

| Required roles | Cryptography engineer and independent reviewer |
| Decision targets | Q-19, Q-21 |

## Outcome

Determine whether the pinned ECDSA implementation can meet recovery, compromise-response and exit requirements without production refresh support.

## Blocked by

- [P2-01: Model trust boundaries and define the experiment suite](p2-01.md)
- [P1-01: Choose the audience and supported onboarding conditions](p1-01.md)

## Acceptance criteria

- [ ] Run DKG, signing and user-quorum reconstruction with test keys on iPhone and in WebAssembly. Check Ethereum and Base transaction signatures.
- [ ] Test service refusal, service-share loss, restored backups and stolen-device scenarios. Distinguish authentication revocation from share replacement.
- [ ] Demonstrate a safe migration procedure when refresh is unavailable. List remaining assets and authorities at the old address.
- [ ] Choose a presignature policy from measured latency and the advisory constraints. Test single use, replay, concurrent requests, crashes and restoration without saved nonce state.
- [ ] Record the protocol-specific irreversible release point and malicious or offline participant behavior. State every erasure and availability assumption.

## Evidence

Pinned experiments, reconstruction/export evidence, compromise traces and a nonce/presignature decision.

## Failure or deferral

If the minimum curve lacks a reviewed safe path, block G2 and release admission. Do not treat backup restoration as cryptographic revocation.
