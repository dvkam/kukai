## Outcome

Produce a dated capability inventory for the experiments, with primary evidence for each claim.

## Blocked by

- [P0-01: Record the charter and assign the open decisions](p0-01.md)

## Acceptance criteria

- [ ] Check CGGMP, FROST, tsslib-rs and BLS candidates at exact revisions. Separate DKG, signing, refresh, resharing, repair and reconstruction support.
- [ ] Record advisories, audited revisions, implementation departures from papers, licenses, nonce requirements and supported curves. Do not equate a paper proof with an implementation audit.
- [ ] Check the proposed Node, pnpm, Rust, OCaml, Swift and verification tools for compatible stable versions. Record supported compiler and verifier combinations.
- [ ] Identify the macOS, Xcode, physical iPhone and browser resources needed. A Linux build cannot establish iOS readiness.
- [ ] Prepare the common experiment format with commands, versions, machine details, outcomes and review requirements. Mark unconfirmed claims as unconfirmed.

## Evidence

A capability matrix, source links with retrieval dates, toolchain proposal and experiment prerequisites.

## Failure or deferral

Report unavailable features and tool conflicts. Do not disable signature checks, change checksums or write substitute cryptographic primitives.
