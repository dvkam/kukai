## Outcome

Choose A1 or B and an account arrangement whose security claims match its signing quorums.

## Blocked by

- [P1-02: Compare three interaction concepts and deliver C1](p1-02.md)
- [P2-02: Test identity independence and device-share storage](p2-02.md)
- [P2-03: Test Ed25519 recovery and independent signing](p2-03.md)
- [P2-04: Test secp256k1 recovery and independent signing](p2-04.md)

## Acceptance criteria

- [ ] Compare explicit signing and recovery quorums for A1 and B. The user must hold a complete exit quorum without another party releasing shares.
- [ ] Compare iOS participation in every service-assisted signature, separate spending/vault accounts, on-chain policy and research-only cryptographic policy. A static threshold quorum cannot depend on transaction amount.
- [ ] For separate accounts, prohibit spending-account authority over vault assets. Test permissions, future deposits, automatic replenishment and cross-account recovery. A current balance is not a lifetime loss cap.
- [ ] Define web-only availability, cumulative service limits, concurrent reservations and requests that always need iOS approval. State which controls require an honest service.
- [ ] Use C1 and the curve experiments to choose the model. Document service-free exit, lost-device limits, combined-compromise residuals and rejected alternatives.
- [ ] Accept the export formats and reconstruction paths established by the curve experiments. Close Q-05 and Q-32 at Phase 2; P3-06 validates the complete exit tool at G3.

## Evidence

An accepted custody decision, quorum diagrams, attack-case results and web-policy requirements.

## Failure or deferral

No decision passes by assuming an amount-dependent threshold. Unresolved minimum-curve recovery or exit failures block this ticket.
