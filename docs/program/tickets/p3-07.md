# P3-07: Run the services-language and Tezos-library comparison

## Outcome

Choose the services language from two implementations of the same authorization and recovery state machine.

## Blocked by

- [P2-12: Review G2 against the minimum curves](p2-12.md)

## Acceptance criteria

- [ ] Use identical frozen requirements, attacker assumptions and input cases. Keep Rust fixed for cryptography, signer and client core.
- [ ] Implement and prove the pure state transitions in Rust with Creusot or Verus and in OCaml with Gospel, Cameleer and Why3. A failed required safety proof disqualifies that candidate.
- [ ] Run the separate OIDC, WebAuthn, PostgreSQL and Tezos encoding library experiments. Compare Tezos serialization against pinned Octez and Taquito results.
- [ ] Score proof effort at 30 percent, library support at 25 percent, defects found at 15 percent, tooling friction at 15 percent and cross-language synchronization at 15 percent. Publish the scoring rubric before measurement.
- [ ] Apply the DEC-023 Rust tie-break within 5 percent. Record raw notes, scores, tool limits and the selected Rust verifier even if OCaml wins services.
- [ ] Choose the Tezos encoding approach and identify how it will work in the Rust client and signer on both platforms.

## Evidence

Both prototypes, proof and integration results, the weighted score sheet and accepted language/library decisions.

## Failure or deferral

If both candidates fail the safety gate, choose neither. Reopen the contradicted requirements or tool assumptions through review.
