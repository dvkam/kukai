## Outcome

Identify code the new wallet can reuse and the obligations attached to each source.

## Blocked by

- [P0-01: Record the charter and assign the open decisions](p0-01.md)

## Acceptance criteria

- [ ] Inventory Kukai web at f0fa7222a039012797383fe4a68594e10b92a888, the referenced iOS repositories and copied third-party files. Record exact source revisions.
- [ ] Assign license identifiers from evidence. Preserve required MIT notices and Apache notices. Separate inherited code from the dual-licensed contributions.
- [ ] List reusable modules, reference-only modules and excluded code. Do not copy code with an unresolved license.
- [ ] Review the day-0 checklist, repository visibility and fork constraints. Propose a feasible publication sequence without changing visibility or rewriting history.
- [ ] Plan a full-history secret scan and a response procedure. Any later scan report records locations and remediation status without secret values.

## Evidence

A provenance inventory, reuse decision and day-0 checklist with unresolved items assigned.

## Failure or deferral

Exclude uncertain code from reuse until the reviewer settles provenance. Do not assume the two root license files resolve every file.
