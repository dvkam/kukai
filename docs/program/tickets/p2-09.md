# P2-09: Decide fees, data services and operational boundaries

| Field | Value |
| --- | --- |
| Phase | 2 |
| Type | Decision |
| Status | Draft |
| Owner | Unassigned |
| Required roles | Operations lead, chain engineers and security reviewer |
| Decision targets | Q-10, Q-18, Q-20 |

## Outcome

Define the services the wallet needs and how users operate or exit when those services fail.

## Blocked by

- [P2-06: Choose custody and enforceable web exposure controls](p2-06.md)
- [P1-03: Set product requirements and measurable quality targets](p1-03.md)

## Acceptance criteria

- [ ] Decide how a zero-balance user pays fees on each release chain. Test sponsorship assumptions and record a no-sponsorship choice where appropriate.
- [ ] Define chain abstraction and cross-chain transaction boundaries without adding swaps or bridges to release 1.
- [ ] Decide whether self-hosted signing ships at launch. Keep the independent exit tool required regardless of this choice.
- [ ] Specify replaceable RPC, indexer, price and metadata sources, provider disagreement handling and cost assumptions. Address the service-free exit tool separately from the normal proxy path.
- [ ] Specify media-proxy SSRF controls, redirect and resolved-IP checks, nested glTF resources, decode limits, isolated delivery and active-content refusal.
- [ ] Record release signing, public-log detection, deployment separation, service backup, incident response and availability requirements. List credentials and paid services as owner-provisioned dependencies.

## Evidence

Accepted operational decisions, API requirements, a media security specification and an outage test matrix.

## Failure or deferral

Do not provision paid services, request real keys in chat or deploy production infrastructure through this ticket.
