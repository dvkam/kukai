# P2-02: Test identity independence and device-share storage

| Field | Value |
| --- | --- |
| Phase | 2 |
| Type | Experiment |
| Status | Draft |
| Owner | Unassigned |
| Required roles | Identity engineer, iOS engineer and security reviewer |
| Decision targets | Q-02, Q-07, Q-25, Q-29 |

## Outcome

Determine which login, storage and backup combinations preserve an independent user factor.

## Blocked by

- [P2-01: Model trust boundaries and define the experiment suite](p2-01.md)
- [P1-01: Choose the audience and supported onboarding conditions](p1-01.md)

## Acceptance criteria

- [ ] Test each selected identity provider and credential manager on the reference devices. Record passkey PRF support and failure behavior.
- [ ] Test cloud-account takeover, cloud recovery, credential sync and device loss. A single recoverable Apple or Google account must not unlock both required factors.
- [ ] Prototype Secure Enclave wrapping and Keychain access controls on a physical iPhone. Compare current-biometric-set and any-biometric policies, reinstall, lock and backup behavior.
- [ ] Test the web fallback or explicitly refuse unsupported credential managers. Record which secrets enter application memory and when.
- [ ] Recommend factor and storage choices with a recovery procedure the user can perform. The custody ticket must accept these results before it closes.

## Evidence

A device/provider test matrix, prototype commands and a reviewed factor/storage recommendation.

## Failure or deferral

Reject unsafe pairings and unsupported fallbacks. Simulator-only results do not establish physical-device protection.
