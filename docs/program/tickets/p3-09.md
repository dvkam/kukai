## Acceptance criteria

- [ ] Verify pinned implementations, external assumption reviews, iPhone and browser feasibility, recovery, compromise-response and exit evidence for every admitted key type.
- [ ] Confirm independent review is funded and booked for each admitted implementation. Record that the later G5 audit is still required.
- [ ] Require admission of Ed25519 for Solana and tz1 and secp256k1 for Ethereum and Base. Record optional tz2, tz3 and tz4 outcomes separately.
- [ ] Choose the default Tezos account type from admitted types and usability evidence. Confirm accepted language, encoding and derivation decisions.
- [ ] Confirm G1, G2, C2 and C3 evidence, proof statuses and the blocked-host exit drill. Mark unsupported L2 as unavailable rather than claiming it passed.
- [ ] Record pass, blocked or fail. Only after a pass, identify the approved Phase 4 requirements from which implementation tickets can be drafted.

## Evidence

An admission matrix, the default-account decision and a G3 record linked to all evidence.

## Failure or deferral

A minimum-key failure blocks release 1. Optional-key failure defers that key. Reopen Phase 2 decisions that a failed required experiment contradicts.
