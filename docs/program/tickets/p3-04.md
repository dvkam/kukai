## Outcome

Test the selected BLS scheme against Tezos account requirements, including reveal proof of possession.

## Blocked by

- [P2-12: Review G2 against the minimum curves](p2-12.md)
- [P2-05: Select or defer the threshold BLS scheme](p2-05.md)

## Acceptance criteria

- [ ] If P2-05 deferred BLS, record the corresponding tz4 deferral without pretending an experiment ran.
- [ ] Otherwise pin the scheme and implementation, review domain separation and test DKG, signing and threshold proof of possession against Octez.
- [ ] Test recovery, retained shares, available refresh or migration, independent reconstruction and exit.
- [ ] Measure the iPhone and browser results and confirm review capacity for the selected implementation.
- [ ] Record admit, defer or fail. Keep tz4 operation capability checks independent of owned-account admission.

## Evidence

A tz4 admission report with proof-of-possession evidence or an explicit deferral decision.

## Failure or deferral

A valid BLS signature without a valid reveal proof of possession does not pass. Defer the optional key type when required evidence is missing.
